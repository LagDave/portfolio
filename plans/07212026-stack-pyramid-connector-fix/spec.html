Why

The Stack section's pyramid renders broken: layers 5–6 are split into a side-by-side grid that shatters the pyramid silhouette, the layer-to-card connector never draws (a stray port circle floats mid-diagram), and the explanation card remounts on every hover, leaving HMR ghost duplicates in dev. The user wants the pyramid enlarged and a working animated connector to the side explanation card.

What

A clean, enlarged 7-row stacked pyramid (monotonic width progression, continuous trapezoid edges) filling its grid column, plus a visible animated SVG connector (draw-in line, marching dashes, pulsing end dot) from the active layer's right edge to the sticky explanation card. Done when the pyramid reads as one continuous shape at lg+, hovering/focusing any layer redraws the connector, and reduced motion gets a static line.

Root causes (diagnosed)

  • Broken shape: layers index 4–5 render in a sm:grid-cols-2 grid; widths not monotonic (96% row under 100% rows).
  • Invisible connector: one motion.path animates pathLength while also setting custom strokeDasharray="3 10" and animating strokeDashoffset — Framer implements pathLength by rewriting stroke-dasharray, so they conflict and the path never shows. Split into two paths: a solid draw-in path (pathLength only) and a dash-flow path (dashoffset only).
  • Ghost cards: key={activeLayer.id} on motion.aside remounts the whole sticky card per hover; move the key to an inner content block.

Assumptions (auto-resolved per -i)

  • Pyramid orientation stays apex-up → widest at bottom (AI-Assisted Building as foundation), matching the existing iceberg metaphor.
  • The two "lower" layers become full stacked rows; the 2-col treatment is removed entirely (also simplifies mobile).
  • Explanation card stays at 24rem column; enlargement comes from removing the 46rem inner cap, taller rows, and bigger type.

Risk

Level: 1 — isolated to one presentational component + its hook. Blast radius: Technologies.tsx is consumed only by App.tsx; useElementConnector.ts only by Technologies.tsx.

  • Connector geometry can go stale while the card is sticky during scroll. Mitigation: hook already re-measures on scroll/resize/ResizeObserver; keep aside mounted so the target ref is stable.
  • Framer pathLength/dasharray conflict must not be reintroduced. Mitigation: two separate paths, each animating one mechanism.
